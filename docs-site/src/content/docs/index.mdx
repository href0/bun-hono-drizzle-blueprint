## Mulai dalam empat langkah

<Steps>

1. **Clone tag rilis terbaru**, bukan `main` — alasannya dan perintahnya di [Project Setup](standards/project-setup/).

2. **Beri nama proyek** dengan `bun run setup`: identitas diganti, modul contoh dihapus, migrasi dibuat ulang. Pilihannya: [Project Setup](standards/project-setup/).

3. **Siapkan database**: PostgreSQL wajib, Redis disarankan; lalu migrasi, admin pertama, dan server dev — [Quick Start](overview/quickstart/).

4. **Buat modul pertama** dengan `bun run scaffold` (wizard atau flag) — varian dan urutan kerjanya di [New Modules](standards/new-module/).

</Steps>

## Pilar arsitektur

<CardGrid stagger>
  <Card title="Kontrak HTTP seragam" icon="document">
    Envelope respons dan kode error tunggal, wire contract `snake_case` dua arah, pesan dwibahasa, dan konvensi list (sort, pencarian, filter). Lihat [HTTP Contract](standards/http-contract/).
  </Card>
  <Card title="Data layer teraudit" icon="setting">
    Repository dasar per jenis tabel; setiap perubahan tercatat atomik. Lihat [Database](standards/database/).
  </Card>
  <Card title="Kanal inbound aman" icon="random">
    Default-deny JWT dengan refresh cookie HttpOnly, kanal inbound bertanda tangan HMAC (mis. webhook vendor) yang fail-closed. Lihat [Auth & Inbound](standards/auth-and-inbound/).
  </Card>
  <Card title="Quality gate berlapis" icon="approve-check-circle">
    Setiap aturan punya penegak mesin (ESLint, dependency-cruiser, test, script). Lihat [Quality Gates](standards/quality-gates/).
  </Card>
  <Card title="Generator & setup" icon="puzzle">
    `bun run setup` menyiapkan proyek baru, `bun run scaffold` membuat modul, webhook, dan adapter vendor dari template yang diverifikasi. Lihat [New Modules](standards/new-module/).
  </Card>
  <Card title="Kontrak API terjaga" icon="open-book">
    OpenAPI dari kode route, snapshot yang di-review, dan dokumen per modul yang di-generate — perubahan kontrak selalu terlihat. Lihat [OpenAPI](standards/openapi/).
  </Card>
</CardGrid>
